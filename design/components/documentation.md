# Documentation

The user docs are in `website/`, as plain markdown that reads well on
GitHub. The hyperjump.io site is built from them, with json-schema's,
hjlint's, browser's, and the other packages', from `../hyperjump.io`, whose
README has how to write them. pact is listed with the components there.

- `website/README.md` introduces it and lists the pages, which are guides:
  install, pipelines, transforming, sources, collecting, async, and
  migrating from v1.
- There's no API reference. The hand-written `.d.ts` files, with their
  JSDoc, are in every editor, and a guide that needs a type says what
  matters about it.
- `npm run check-website` runs every example in `website/` against `src/`
  and checks each `// value` comment and printed `text` block
  (`scripts/check-website.js`), and CI runs it, so an example can't drift
  from what the code does. It type-checks every example, strictly, against
  the `.d.ts` files too, so the examples are `typescript` blocks.
- A feature that isn't released gets `*Coming soon*` on its own line under
  its heading. `npm version` replaces it with `*Added in vX.Y.Z*`
  (`scripts/version-docs.js`). v2's pages describe v2 as a whole, without
  markers, with what changed in [Migrating from v1](../../website/migrating.md).
- The `docs-changed` workflow tells hyperjump.io to rebuild when `website/`
  changes on the branch the site builds from, `v2` for now. It needs a
  `SITE_DISPATCH_TOKEN` secret.

## Rejected

- **TypeDoc, published to pact.hyperjump.io**, as in v1. Its pages were the
  declarations split into pieces, which the `.d.ts` files already are, with
  no guides, and it was a site of its own instead of being with the other
  Hyperjump packages. hyperjump.io rejected API pages generated by TypeDoc
  for the same reasons.
